01 / The problem

Safe parts can become
an unsafe whole.

One agent holds a fragment of a record. Another holds a different fragment. A downstream agent combines them into a governed object and proposes an action using it.

Each contribution can be admissible in isolation while the composed action violates trusted policy. Multi-agent safety depends on how information is combined and used.

The controlled comparison keeps the downstream proposal fixed and changes the reader’s access from individual artifacts to their union.

02 / The approach

Measure the distinction.
Enforce it.

Blocking every action would also remove useful capabilities. FlowReview measures whether a system blocks denied use while completing the authorized use required by the task.

It connects this safety target to three capabilities that carry the permission distinction through execution.

  1. 01

    Object resolution

    What is being acted on?

    Identify the governed object made available by the agents’ combined information.

  2. 02

    Permission ranking

    Is this use authorized?

    Bind the proposed action to the exact object and its trusted permission.

  3. 03

    Deterministic enforcement

    What actually executes?

    A runtime commit gate carries the validated decision through to execution.

What this example establishes +

Individual-artifact review commits the reconstructed credential under both policies. Combined-artifact review blocks it under DENY and commits it under ALLOW. This isolates the permission distinction that composition makes necessary.

Authorized supply and full-task completion are separate outcomes. This composer supplies the authorized credential but fails the exact-report task check because it adds instruction text.

What the specialist actually decides +

The specialist selects a candidate that matches the trusted policy and object binding, or returns no action when use is denied. The runtime verifies the selected action before execution. The LLM selects an action within an explicit permission structure.

This is the coordinator’s sole policy-correctness failure among 480 confirmation graphs with the runtime lineage record. All four isolated specialists select the correct action on this graph. In the paired DENY case, they return no action.

Why measured utility improves +

Both modes execute the same first six calls, including the event and invitation. The gate blocks the seventh call. The benchmark’s utility check requires the final state to contain only permitted task changes, so the extra email action changes the native run’s utility from success to failure.

Across 24 fresh Sonnet pairs, attack-target commits fall from 21/24 to 0/24 and task utility rises from 9/24 to 21/24. Aggregate legitimate-action supply remains 5/24 in both modes.

04 / Evidence

Safety that preserves
the authorized task.

The capability ladder tests what changes when the system can identify the exact object, bind its permission, and enforce the resulting decision.

A

Distribution matters more than team size alone.

At four information contributors, increasing the team from 8 to 16 agents preserves full object coverage. At 15 contributors, coverage falls to 149/168. The distribution of information determines the resolution challenge.

B

Place each capability where it can be verified.

All four isolated permission specialists pass the policy-correctness test. In a separate assembly comparison, moving assembly to the runtime raises authorized supply from 0.350 to 1.000.
