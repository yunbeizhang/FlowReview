THE PROBLEM

Safety changes when information comes together.

One agent sees part of a record. Another sees a different part. A downstream agent can combine their contributions into a governed object and propose an action using it. Each contribution may be admissible in isolation, while the composed action violates trusted policy.

Preventing every action would remove useful capabilities too. FlowReview asks whether the system can distinguish prohibited use from the authorized use required by the task.

FLOWREVIEW

Measure the distinction. Carry it through execution.

Paired policy evaluation makes both outcomes part of the safety target. A system succeeds when it blocks denied use and completes the required authorized use. FlowReview connects that measurement to three capabilities.

01

Object resolution

Identify the governed object made available by the agents’ combined information.

02

Permission ranking

Bind the proposed action to the object and its trusted permission.

03

Deterministic enforcement

Ensure that execution follows the permission decision.

MAIN RESULTS

Block denied use. Complete authorized use.

Object binding and deterministic enforcement raise selective correctness from 0% to 99.6% and reduce verbatim disclosure to 0% in the pooled 24-round evaluation.

Three complementary capabilities

WHAT WE FIND

Multi-agent safety requires control over composed information flows.

Composition changes what is actionable.

Local admissibility can coexist with a prohibited downstream action. Reviewing the assembled object exposes the missing permission distinction.

Delegation can lose the context of authority.

Content can survive a handoff while its lineage and permission attribution diverge. Reliable lineage and correct permission decisions are distinct capabilities.

Correct review must survive execution.

Object binding, runtime enforcement, and the placement of assembly capabilities determine whether safety preserves the authorized task.
